# 사운드보드 사용 안내

[파일 구성과 전달 순서 보기](START-HERE.html)

요청을 보고 소리를 만들고, 게임에서 들어보는 로컬 작업실입니다. 디자이너는 **Windows PC에서 SoundBoard.exe만 실행하면 되며 Unity를 설치할 필요가 없습니다.** 받은 ZIP은 먼저 풀고, EXE와 나머지 폴더를 함께 보관합니다.

## 소리 하나 작업하기

1. 왼쪽에서 요청을 고르고 설명 옆 **사용 장면**을 확인합니다. 영상은 무음 참고용이며, 넣은 소리와 자동으로 맞춰 재생하지 않습니다.
2. **파일 넣기**로 소리를 넣고 듣습니다. 필요하면 음량을 조절합니다.
3. **OGG로 저장**합니다. 원본은 그대로 보관하고 게임용 파일을 따로 만듭니다.
4. **게임에 테스트 적용 → 게임 실행**을 누르고 해당 장면을 직접 플레이합니다.

**게임 연결 예정**은 제작·미리듣기·저장까지 가능합니다. 해당 사건에 소리가 나도록 연결하는 코드는 개발 담당자가 추가합니다. 현재 요청은 30개이며 게임 시험 슬롯은 9개입니다. 일반 타격은 여러 블록과 벽이 공유하고, 현재 인게임 음악은 타이틀에서도 들립니다.

음악은 **최대 10분**까지 사용할 수 있습니다. WAV·MP3·FLAC·OGG 등 변환기가 읽는 오디오를 넣으면 요청에 맞게 48kHz OGG로 변환합니다. 파일당 원본 한도는 256MiB입니다. 긴 음악은 무손실 FLAC을 쓰면 WAV보다 전달 용량을 줄일 수 있습니다. 반복 구간을 지정해 게임에 적용하면 그 구간만 잘라 반복합니다.

## GitHub로 주고받기

작업 저장소는 [152gamelabs/star-rush-neon-sound](https://github.com/152gamelabs/star-rush-neon-sound)입니다. 비공개이므로 디자이너를 초대하고 수락한 뒤 사용합니다. 프로그램은 [최신 다운로드 페이지](https://github.com/152gamelabs/star-rush-neon-sound/releases/latest)에서 받습니다. [전달할 메시지와 주소](HANDOFF.md)를 그대로 사용할 수 있습니다.

압축을 풀면 Sound 저장소의 공통 이력이 준비되어 있습니다. 처음 한 번 **CONNECT-GITHUB.cmd**를 실행해 본인의 GitHub 아이디를 입력하고 브라우저에서 로그인·승인한 뒤 **SoundBoard.exe**를 실행합니다. GitHub Desktop은 필요하지 않습니다. 연결 파일은 계정·기록자 설정과 저장소 접근 확인을 하며, 원본 소리를 커밋하거나 올리지는 않습니다.

프로그램 ZIP은 GitHub의 **Releases(배포 파일)**에 첨부하거나 파일로 직접 전달합니다. 이후 소리 작업은 Sound 저장소로 주고받습니다. 큰 프로그램 ZIP을 소리 작업 폴더에 매번 커밋하지 않습니다. [GitHub 배포 파일 안내](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

**내가 요청 등록 → 올리기 → 디자이너 받기 → 제작·저장 → 커밋·올리기 → 내가 받기·확인**

- 작업을 시작하기 전에 **받기**로 최신 요청을 가져옵니다.
- 작업을 마치면 변경 파일을 골라 **커밋**하고 **올리기**를 누릅니다.
- **커밋**은 내 컴퓨터에 기록, **올리기(push)**는 GitHub에 공유, **받기(pull)**는 상대 변경을 내 컴퓨터로 가져오기입니다. 커밋만 하면 상대에게 전달되지 않습니다.
- 받은 제출본은 보드에서 열어 OGG 변환 후 게임에 테스트 적용합니다. 받기만으로 실행 중인 게임 소리가 자동 교체되지는 않습니다.

현재 보드의 Git 공유 범위는 **Sound 폴더**입니다. 요청·작은 장면 자료·원본 음원·조정값을 주고받습니다. 긴 고용량 원본이 저장소 한도를 넘으면 Git LFS를 별도로 설정하거나 작업 내보내기 ZIP으로 전달합니다.

## 무엇이 업데이트되나요?

| 변경한 것 | 전달과 적용 |
|---|---|
| 소리·음량·반복 구간 | 사운드 저장소에 커밋·올리기 → 상대가 받기 → OGG 변환·게임 테스트 적용 |
| 요청 설명·장면 자료 | 개발자가 수정·올리기 → 상대가 받기 → 목록 새로고침 |
| 게임 코드·규칙·화면 | 개발자가 Unity에서 수정·다시 빌드 → 최신 게임 실행판 전달. 코드만 올려도 기존 EXE가 바뀌지는 않음 |
| 사운드보드 프로그램 | 최신 프로그램 패키지로 갱신. 기존 Sound 작업 데이터는 유지 |
| 개인 게임 진행·설정 | 각 PC에 보관. 사운드 Git·작업 내보내기에서 제외 |

게임 업데이트는 저장 형식의 호환성을 유지해야 이어할 수 있습니다. 사운드 테스트용 저장은 실제 플레이 저장과 분리되어 있습니다.

## GitHub 없이 전달하기

**작업 내보내기**로 만든 ZIP을 보내도 됩니다. 이것은 요청·참고 자료·제출본을 담는 작업 ZIP이며, 프로그램 전체 ZIP과 다릅니다. 받은 ZIP은 먼저 별도 폴더에 풀고 새 제출본을 확인해 합칩니다. 기존 Sound 폴더 전체를 지워서 교체하지 않습니다.

프로그램을 처음 줄 때는 **프로그램 ZIP**, 소리만 주고받을 때는 **GitHub 또는 작업 ZIP**을 사용합니다. 내 컴퓨터의 127.0.0.1 주소는 상대방에게 공유하는 주소가 아닙니다.

## 파일 위치

| 폴더·파일 | 내용 |
|---|---|
| requests.json | 제작 요청. 개발 담당자가 관리 |
| context/scenes/ | 작은 장면 사진·무음 영상 |
| submissions/ | 원본·조정값·메모. 이전 제출도 보존 |
| bakes/ | 다시 만들 수 있는 OGG 변환본 |
| preview/ | 게임 시험 음원과 별도의 시험 저장 |

출시 반영은 개발 담당자가 실제 게임 이벤트에 연결하고 확인한 뒤 완료합니다. 게임에서 시험했다는 사실과 출시 반영 완료는 구분합니다.
